# Contributing

Bug reports, feature ideas, documentation fixes and pull requests are all welcome.

---

## Reporting Bugs

Check the [Issues page](https://github.com/d3uceY/Cokpyt/issues) first.

A useful report includes:

1. OS and version
2. Python version (`python --version`)
3. pip version (`pip --version`)
4. Cokpyt version (shown in **Settings**)
5. Steps to reproduce
6. What you expected, and what happened
7. Console output from Cokpyt - hit **copy** in the console header, or open **Settings → View the log**.

---

## Suggesting Features

Open an issue with a `[Feature]` prefix. Describe the problem you are trying to solve, and how the
feature would address it. Screenshots and references to how other tools do it help.

## Setting Up the Dev Environment

| Tool | Version |
|---|---|
| [Go](https://go.dev/dl/) | 1.23 or later |
| [Wails CLI](https://wails.io/docs/gettingstarted/installation) | v3 |

```bash
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
```

Node.js is not required: there is no frontend build step.

```bash
git clone https://github.com/d3uceY/Cokpyt.git
cd Cokpyt
wails3 dev
```

Other commands:

```bash
wails3 task test       # go test ./...
wails3 task compile    # regenerate bindings, then build
wails3 task run        # run the binary that is already built
node scripts/check-frontend.mjs   # parse every frontend module
```

```bash
wails3 build       # current OS
wails3 package     # NSIS installer on Windows, .app bundle on macOS
```

Cross-compiling is a matter of setting `GOOS` and `GOARCH`. Linux and macOS builds need
`CGO_ENABLED=1` and a platform toolchain; Windows does not.

## Project Structure

```
Cokpyt/
  main.go                 -- Entry point: Wails options, window, service registration
  app.go                  -- The service the frontend calls; the whole API surface
  backend/
    environments/         -- Finds every Python environment on the machine
    pip/                  -- Package operations, PyPI search, doctor, cleanup, history
    platform/             -- OS-specific process handling
  frontend/
    index.html            -- The shell: sidebar, page head, console panel, status bar
    css/app.css           -- The design system, hand-written
    js/                   -- Router, store, DOM helpers, and one module per page
    bindings/             -- GENERATED by `wails3 generate bindings -b`. Do not edit.
  build/                  -- App metadata, icons, installers, per-platform builds
  scripts/                -- check-frontend.mjs, fetch-icons.ps1
```

A public method on `App` is callable from the frontend once the bindings are regenerated
(`wails3 task bindings`).

## Making a Pull Request

1. Branch from `main`.
2. Make your changes and confirm the project builds (`wails3 build`).
3. If you changed frontend code, make sure it parses, and add a Go test for any non-trivial logic:
   ```bash
   node scripts/check-frontend.mjs
   go test ./...
   ```
4. Commit with a message describing what changed and why.
5. Push and open a pull request against `main`, linking related issues.

Keep pull requests focused. One fix or feature per PR.

## Style Guidelines

**Go**
- Run `gofmt` before committing. Return errors rather than panicking in library code.
- Comments explain *why*, especially where a decision looks odd.
- Non-trivial logic leaves one runnable check behind. Table-driven tests with real-world input beat
  fixtures.

**JavaScript**
- Plain ES modules. No framework, no bundler, no `package.json`.
- Build DOM with `ui.js`'s `h()` helper rather than `innerHTML`, so user strings are never parsed as
  markup.
- Pages export `meta`, optional `actions`, and `render`. Data loading lives in `store.js`.

**CSS**
- `app.css` is the design system: square corners, 1px borders, uppercase micro-labels, one accent
  colour (`#0048ad`) that means "this is the action", and no decoration that carries no information.
- Every value is a token in `:root`. A dark value belongs in `[data-theme="dark"]`, not a media query.
- No UI library and no icon font. The icons are a small SVG sprite, regenerated with
  `scripts/fetch-icons.ps1`.
